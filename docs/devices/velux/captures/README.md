# Raw RX captures — Velux BG-RC011-02 (KLI 31x) + window actuator

Frames sniffed with an SX1262 (Heltec V4.2) running this repo's ESPHome
component in receive mode. Radio config (confirmed correct, see
`../velux-frame-analysis.md` §1): 868.95 MHz, 2-FSK, 38.4 kbps, 19.2 kHz
deviation, NRZ, no shaping, sync word `57 FD 99`, 512-bit preamble, radio CRC
off, fixed-length RX widened to 64 bytes.

**How to read a line:** `rssi=<dBm>` then the 64 bytes the radio delivered for
that packet, MSB-first as RadioLib hands them over. A frame starts at byte 0
(the sync word is consumed by the radio) and ends where the trailing preamble
run (`55`/`AA`/`FF`) begins; everything after that is the next frame's preamble
or post-frame idle, not payload.

**Devices seen (source address / device-id bytes at idx8-9):**
- `7E 51 D2` / `F4 8F` — the window wall remote
- `7E 46 94` / `AD 31` — a second (identical) remote
- `7E 5A 11` / `35 29` — a third remote (appeared during an anlern attempt)
- actuator (destination) is `10 04 01` (a `10 05 01` variant also appears)

**The open question these are here to settle:** none of these validate a
standard CRC-16/KERMIT at any length/offset/bit-transform, and they run to
~48 bytes (past the 34-byte max the 5-bit size field can encode), while the
demod is provably good. See `../velux-frame-analysis.md` §3 and §7.
